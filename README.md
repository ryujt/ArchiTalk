# ArchiTalk

프로젝트 폴더에서 실행하고 웹 대화로 요구사항과 소프트웨어 아키텍처를 함께 설계하는 Rust CLI입니다. 로컬에 설치한 Claude Code 또는 Codex를 호출하고, 결과는 프로젝트의 `docs/architecture/` 아래에 Markdown 문서로 남깁니다.

ArchiTalk의 목적은 기술 이름부터 고르는 대신, **무엇을 만들고 왜 그런 구조를 선택하는지** 설명할 수 있게 돕는 것입니다. 프로젝트 규모·분야·업무 흐름·실패 영향을 차근차근 질문하고, 비즈니스 요구를 아키텍처 드라이버와 검증 가능한 품질 시나리오로 구체화합니다. 설계 역할이 대안과 트레이드오프를 제안하고, 별도의 비판 검토 역할이 전체 문서의 근거와 모순을 확인합니다. 사용자는 제안을 검토하고 결정하며, 문서에는 확인된 사실·가정·제안·미정 사항을 구분해 남깁니다.

## 설계 과정과 결과물

대화 → 드라이버 식별 → 품질 시나리오 → 대안·택틱·스타일·패턴 비교 → 설계 결정과 ADR → 구현·운영 검증으로 이어집니다. 새 답변으로 전제가 바뀌면 관련 요구와 결정도 다시 검토합니다. 질문이 남아 있어도 초안을 만들 수 있지만, 답하지 않은 수치나 정책을 확정값으로 채우지 않고 조건부 대안·확인 방법·결정 조건을 남기도록 합니다.

새 설계는 **주 아키텍처 문서와 9종 상세 문서, 총 10개**로 생성합니다. 중요한 선택을 드라이버(`DRV`)·품질 시나리오(`QA`)·대안(`ALT`)·결정(`ADR`)·검증(`VAL`) ID와 문서 링크로 연결합니다.

문서는 **한 종류씩 순차 요청**합니다. 요구·드라이버 → 품질 시나리오 → 대안 → 결정 → 구현·운영 검증 → 잡플로우 → 상태도 → 화면설계 → 네비게이션을 작성하고, 주 아키텍처 문서를 마지막에 종합합니다. 앞 문서의 실제 ID와 제목 앵커를 다음 문서에 전달하며, 마지막에 전체 문서 간 연결을 검증하고 독립 비판 검토를 진행합니다.

| 파일 | 설명 |
| --- | --- |
| `아키텍처-설계.md` | Method-R 매크로·시스템·모듈·상세 설계와 시스템 구성도, 데이터·계약, 실행·배포, 문서 지도와 미정 사항 |
| `요구사항과-아키텍처-드라이버.md` | 사업 목표, 기능·품질·제약, 구조를 바꾸는 핵심 요인, 첫 출시 범위와 제외 항목 |
| `품질속성과-검증시나리오.md` | 자극·환경·대상·응답·측정 기준, 불변조건과 협의할 목표, 미정 수치의 확인 방법 |
| `설계대안과-트레이드오프.md` | 단순한 기준안부터 가능한 대안 비교, 얻는 효과와 감수할 비용, 제외 이유와 필요한 실험 |
| `아키텍처-결정기록.md` | ADR별 맥락·상태·대안·선택 이유·단점·완화·재검토 조건 |
| `구현과-운영검증.md` | 구현 순서와 의존성, 요구·결정별 검증, 관측·실패·복구·운영 책임 |
| `네비게이션.md` | 화면 이동과 판단, 실패·복귀 흐름, 화면설계 문서의 실제 장면 링크 |
| `잡플로우.md` | 객체의 책임·공개 계약과 협력 순서, 성공·실패·결과 미확인 처리 |
| `상태도.md` | 상태 소유자, 초기화·이벤트·전이 조건·불변조건과 금지 전이 |
| `화면설계.md` | 화면·장면별 배치, 입력·로딩·오류·빈 상태, 접근성과 반응형 동작 |

구조 설계는 **Method-R**을 사용합니다. 매크로에서는 시스템을 하나의 블랙박스로 두고 외부의 업무 요청과 결과를 확인합니다. 시스템에서는 책임과 상태 소유권을, 모듈에서는 오케스트레이터와 작업자의 좁은 계약을 정하며, 위험하거나 불확실한 부분만 상세화합니다. 서비스 경계를 나누었다고 분산 배포나 마이크로서비스를 전제하지 않습니다. [생성·검토 규칙](prompts/design-package-format.md)에 구체적인 계약을 기록했습니다.

문서는 SmartMD 메타데이터·콜아웃·표와 `navigation`·`jobflow`·`state`·`layout` 다이어그램을 보존합니다. 주 문서의 시스템 구성도는 Mermaid flowchart로 책임 경계·구성요소·데이터 소유자·인터페이스를 보여주며, 논리 구조와 실제 배포를 구분합니다. 데이터·배포 등 추가 보조 도표도 사용할 수 있습니다. 도표 수와 설명의 깊이는 실제 업무와 위험에 따라 달라집니다. 확인된 비 UI 프로젝트도 네비게이션·화면설계 문서를 유지하고 비적용 이유와 CLI/API 등의 대체 인터페이스를 설명합니다. HTML 프로토타입은 생성하지 않습니다.

검토 화면에서 종류별 문서를 선택하고 문서 사이의 링크로 이동할 수 있습니다. 비판 검토·내용 확정·저장은 **전체 패키지**를 대상으로 합니다. 형식·참조 검사는 누락과 깨진 연결을 잡지만, 모델이 제안한 근거·측정값·업무 판단의 정확성은 사용자의 검토가 필요합니다.

## 빠른 시작

현재 AI 실행을 검증한 환경은 **macOS**입니다. 지원 프로필은 Claude Code **2.1.326·2.1.327**, Codex CLI **0.169.0**이며 둘 중 사용할 도구 하나를 설치하고 먼저 로그인하세요. 다른 버전은 `doctor`에서 실제 확인한 버전과 미지원 이유를 안내합니다. 로컬 CLI를 사용해도 모델 처리는 해당 도구의 서비스·인증·이용 조건을 따릅니다.

소스 설치에는 Rust/Cargo와 C 컴파일러가 필요합니다.

```bash
./install.sh
cd /path/to/your-project
architalk
```

`install.sh`는 소스 체크아웃의 위치를 기준으로 빌드하므로 어느 폴더에서 실행해도 됩니다. `sudo` 없이 Cargo의 기본 설치 경로에 설치하며, 보통 `~/.cargo/bin/architalk`가 됩니다. Cargo의 `install.root`, `CARGO_INSTALL_ROOT`, `CARGO_HOME` 설정도 따릅니다. 같은 명령으로 재설치·업데이트할 수 있습니다.

설치 경로를 지정하려면 `./install.sh --prefix /원하는/경로`를 사용하세요. 실행 파일은 해당 경로의 `bin/architalk`에 설치됩니다. 설치된 `bin` 폴더가 `PATH`에 없다면 셸의 `PATH`에 추가한 뒤 새 터미널을 여세요. 스크립트는 셸 설정 파일을 자동 수정하지 않습니다.

브라우저가 열리면 프로젝트를 소개하고 질문에 답하세요. 모델·생각 수준은 **도구 설정**에서 선택합니다. **다음 단계로 · 초안 만들기**를 누르면 질문을 모두 마치지 않아도 현재 내용으로 10종 문서 작성과 비판 검토를 진행합니다. 검토 화면에서 문서 종류를 바꾸어 확인한 뒤 전체를 초안으로 저장하거나, 준비 조건을 충족한 버전을 검토본으로 확정하고 저장할 수 있습니다.

응답을 기다리는 동안 대화 화면에 작성 중 메시지가 표시됩니다. 답변이 완료되면 최신 대화와 입력창이 보이도록 이동하며, 넓은 화면에서는 대화도 작업 영역의 너비에 맞춰 확장됩니다.

좌우 사이드바는 각 패널의 안쪽 경계 버튼으로 접고 펼칠 수 있습니다. 왼쪽은 오른쪽 끝, 오른쪽은 왼쪽 끝에 버튼이 있으며 접어도 화면 가장자리에 다시 여는 버튼이 남습니다. 왼쪽 사이드바의 **문서에 반영하기** 단계 바로 아래에 있는 프로젝트 파일 목록에서 Markdown·텍스트·지원하는 코드 파일을 열면 별도 문서 탭으로 표시합니다. **대화** 탭으로 돌아가 기존 대화를 이어가고, 파일 우클릭 메뉴에서 경로와 파일 이름을 복사할 수 있습니다. 숨김·인증 파일, symlink, 바이너리와 빌드·의존성 폴더 등은 목록에서 제외하며 지원하지 않는 형식은 표시하지 않습니다.

시작 화면·대화·문서 검토·설정에 공통 색상·글자·간격과 버튼 스타일을 적용했습니다. 넓은 화면은 작업 영역을 채우고, 좁은 화면은 패널을 겹쳐 열어 본문 공간을 확보합니다. [화면 개선 설계](docs/design/20261118-144512/ux-ui/ux-ui-improvement.md)에 배치와 검증 기준을 기록했습니다.

도표는 처음에 전체가 보이도록 맞춥니다. 도표의 **＋/−**로 확대·축소하고 **전체 보기**로 초기화하세요. 확대하면 드래그나 방향키로 이동할 수 있으며 일반 휠은 문서를 스크롤합니다. 전체 문서 저장 창은 파일 목록을 기본으로 보여주고 원문은 파일별로 펼쳐 봅니다. 저장 버튼은 목록 아래 고정 영역에 표시합니다.

문서 생성 중에는 **문서 3/10 완료**처럼 진행 수와 현재 문서를 보여줍니다. 검증을 통과해 기록된 중간 문서는 프로젝트 DB에 보존합니다. 중단 후 **남은 문서 이어 만들기**를 누르면 이미 완료한 문서를 재사용하고 실패한 종류부터 이어갑니다. **처음부터 새로 생성**은 새 생성 기록을 만들며 이전 대화와 완성 초안을 보존합니다. 중간 문서는 전체 검증 전까지 초안으로 승인하거나 파일로 저장할 수 없습니다.

대화 작업이 실패하거나 중단됐다면 **답변 다시 받기**로 마지막 사용자 입력에 대한 답변을 다시 요청할 수 있습니다. 기존 메시지를 중복 추가하지 않으며, 현재 도구 설정으로 새 작업을 시작합니다. 업데이트 후에는 실행 중인 서버를 Ctrl+C로 종료하고 `architalk`를 다시 실행해 새로 열린 주소에 접속하세요. 저장된 대화를 선택하면 복구 화면에서 이어갈 수 있습니다.

```bash
architalk --no-open                  # URL만 출력
architalk --project /path/to/project # 실행 폴더를 명시
architalk --port 8087                # 필요할 때 포트 지정
architalk doctor                     # 설치·버전·옵션만 확인, 모델 호출 없음
architalk --config /path/to/config.toml
```

기본은 현재 폴더이며 Git 루트로 자동 이동하지 않습니다. 종료는 Ctrl+C입니다. 자동 브라우저 열기가 실패해도 터미널의 URL로 사용할 수 있습니다. URL에는 이번 프로세스의 로컬 접근 토큰이 있으므로 공유하지 마세요.

## 모델과 생각 수준 설정

공통 설정 파일은 `$XDG_CONFIG_HOME/architalk/config.toml`, 환경변수가 없으면 `~/.config/architalk/config.toml`입니다. [설정 예시](config.example.toml)를 복사하거나 `--config`로 사용할 공통 파일을 지정하세요. 파일이 없어도 기본 설정으로 시작합니다. 웹에서 저장한 에이전트·모델·생각 수준·시간 제한은 이 파일에 기록하며 다른 프로젝트의 다음 작업에도 적용합니다. 문서 저장 폴더와 프로젝트 기록은 각 프로젝트에 따로 보관합니다.

- Claude는 `-p`, Codex는 `exec`로 비대화형 호출합니다. Codex의 `-p`는 프로필 옵션이며 현재 격리 프로필에서 named profile은 지원하지 않습니다.
- 기본 도구·모델·생각 수준과 대화/설계 작성/비판 검토 역할별 설정을 선택할 수 있습니다. 모델과 생각 수준은 알려진 값 목록에서 고르거나 바로 아래 입력란에 직접 입력하세요. 역할의 목록은 선택한 도구를 따르며, 도구를 바꿔도 입력한 값은 유지합니다. 기본 설정의 빈칸은 CLI 기본값, 역할 설정의 빈칸은 선택한 도구의 기본 설정을 사용합니다.
- 목록은 알려진 값의 예시이며 계정·CLI·모델별 지원을 보장하지 않습니다. 목록에 없는 모델 ID나 생각 수준도 직접 입력할 수 있습니다. 생각 수준은 영문·숫자·`_`·`-`로 최대 32자이며 `-`로 시작할 수 없습니다.
- 변경은 다음 작업부터 적용하고 현재 작업의 설정은 유지합니다. 선택한 모델이 생각 수준을 지원하지 않으면 오류를 표시하며 자동으로 다른 값으로 바꾸지 않습니다.
- 작업 시간 제한은 기본 **1800초(30분)**이며 설정에서 **10~3600초(최대 1시간)**로 조정할 수 있습니다. 생각·응답 생성을 포함한 모델 요청 1회 기준이며 설계 생성과 후속 비판 검토는 각각 제한을 적용합니다. 여러 문서를 생성하는 시간은 모델과 생각 수준에 따라 달라집니다. 설정 파일에 명시한 기존 값은 그대로 유지하고, 파일이나 항목이 없을 때 새 기본값을 사용합니다.
- 실행파일 경로는 신뢰된 사용자 설정 파일에서만 바꿀 수 있습니다. 웹은 임의 명령·환경변수·도구 권한을 추가하지 못합니다.
- 설치 진단은 로그인이나 특정 모델 지원을 검증하지 않습니다. 실제 AI 작업에서 인증 오류가 나면 해당 CLI의 터미널에서 처리한 뒤 명시적으로 재시도하세요.

## 문서와 대화 기록

문서 탭에서는 녹음으로 수정 지시를 남길 수 있습니다. 먼저 문서의 **음성 전사 설정**에서 OpenAI API 키와 전사 모델을 설정하세요. 키가 없으면 녹음 버튼을 눌렀을 때 안내하고 마이크 권한을 요청하지 않습니다. 키가 있으면 브라우저의 마이크 권한을 받아 녹음하며, 문서를 열거나 클릭·선택·복사한 위치와 경과 시간을 함께 기록합니다. 녹음을 마치면 음성을 전사하고 **실제 발화 구간과 문서 조작을 시간순 타임라인으로 합쳐 클립보드에 복사**합니다. 같은 시각이면 발화를 먼저 표시하며 파일·제목 앵커·선택 문장·코드 줄 위치를 함께 남깁니다. 이 지시는 문서를 자동 수정하거나 AI 채팅으로 전송하지 않습니다.

복사는 브라우저에서 먼저 시도하고, 권한·포커스·클릭 직후 조건 때문에 거절되면 mdview처럼 실행 중인 Mac의 `pbcopy`로 처리합니다. 전사 응답을 기다리는 동안 클릭 권한이 만료돼도 이 로컬 경로로 복사할 수 있습니다. 두 방법이 모두 실패하면 사유와 전체 내용을 보여주므로 **복사** 버튼으로 다시 시도하거나 텍스트를 선택해 `⌘C`로 복사하세요. 로컬 복사는 인증된 서버에 텍스트를 전달해 클립보드에 쓰기만 하며 기존 클립보드를 읽거나 복사 내용을 파일로 보관하지 않습니다.

전사는 로컬 Claude/Codex와 별도로 OpenAI Audio API를 사용합니다. 음성만 전송하고 문서 본문과 클릭·선택 기록은 업로드하지 않습니다. 오디오·전사·위치 기록은 파일로 보관하지 않으며 페이지를 닫으면 사라집니다. 전사 키와 모델은 공용 설정 위치의 별도 비밀 설정 파일에 보관하고 프로젝트 DB·일반 AI 설정 snapshot에 포함하지 않습니다. 파일 키를 삭제해도 `OPENAI_API_KEY` 환경변수가 있으면 해당 키를 사용합니다. 음성 크기는 최대 20MiB, 요청 제한은 120초이며 설계 AI의 1800초 기본 제한과 별개입니다. 기본 전사 모델은 mdview와 같은 **`whisper-1`**이며 실제 발화 구간의 시작·종료 시간을 요청합니다. 이미 저장한 모델 선택은 유지하므로 기존에 `gpt-transcribe` 등을 사용했다면 **음성 전사 설정**에서 `whisper-1`을 선택하고 저장하세요. 시간 정보를 주지 않는 모델의 전체 전사문은 **시간 정보 없는 전사문**으로 분리하며 클릭 시각에 임의 대응시키지 않습니다. 실제 구간과 전체 원문이 일치하지 않으면 원문도 별도로 보존합니다. [OpenAI 타임스탬프 안내](https://developers.openai.com/api/docs/guides/speech-to-text.md#timestamps)

녹음 시작 이벤트를 공통 시간 기준으로 사용하고 중지 시점에 기록을 고정하므로 전사 응답을 기다리는 시간이 타임라인에 더해지지 않습니다. 밀리초 표시는 음성 인식 구간 경계까지 밀리초 정확도라는 뜻은 아닙니다. OpenAI 안내상 `whisper-1` API는 **2027년 2월 26일 종료 예정**이며, 종료 후에는 타임스탬프를 지원하는 전사 방식으로 조정해야 합니다. [공식 지원 일정](https://developers.openai.com/api/docs/deprecations#2026-08-26-transcription-models)

대화·근거·설계 버전·실행·저장 상태는 프로젝트의 `.architalk/workspace.db`에 보관합니다. 프로젝트별 CLI 실행 디렉터리와 임시 파일도 `.architalk/runtime/` 아래에서 만들고 정리합니다. 공용 설정 파일에는 대화·프로젝트 경로·실행 이력을 저장하지 않습니다. `.architalk/`를 Git 제외 목록에 추가하세요. 앱은 기존 `.gitignore`를 자동 수정하지 않습니다.

기록을 초기화하려면 서버를 종료하고 해당 프로젝트의 `.architalk/`를 삭제한 뒤 다시 실행하세요. 실행 중 폴더나 DB를 삭제·교체해도 이전 메모리 내용을 새 폴더에 복원하지 않습니다. 서버가 변경을 감지하면 이전 내용 표시와 작업을 중단하고 재시작을 안내합니다. 브라우저는 대화 본문을 저장하지 않습니다. 공통 AI 설정은 초기화 후에도 유지합니다.

출력 예시는 `docs/architecture/회원-알림-서비스/` 아래의 10개 Markdown 파일과 저장 확인용 manifest입니다. 다음 저장은 `회원-알림-서비스-개정-2/` 같은 새 폴더를 사용하고 기존 문서를 덮어쓰지 않습니다. 저장 전에 경로·파일·내용을 확인할 수 있습니다. **초안 버전**에서 이전 초안을 선택하면 당시 문서와 원문을 확인하고 그 버전 전체를 저장할 수 있습니다. 파일 저장과 내용 수락은 구분하며, 과거의 단일 문서 초안도 원문과 기존 저장 방식을 유지합니다.

0.3부터 상태 DB는 schema 3을 사용합니다. schema 1·2 DB를 처음 이행할 때 WAL의 확정 내용까지 포함한 백업을 `.architalk/`에 만들며, 이전 schema만 지원하는 실행 파일은 업그레이드한 DB를 열 수 없습니다. 기존 대화·완성 문서·저장 이력은 유지합니다.

검토 화면에서 Markdown 제목·표·SmartMD 요소와 다이어그램을 실제로 표시합니다. **현재 문서의 Markdown 원문 보기**를 펼치면 저장할 원문을 확인할 수 있습니다. 렌더러와 라이브러리는 바이너리에 포함되어 CDN이나 Node 설치 없이 동작하며, 표시할 수 없는 도표는 해당 위치에서 오류와 원문을 보여줍니다.

프로젝트 자료는 선택한 README·구성 파일의 제한된 텍스트만 전달합니다. 숨김/인증 파일·symlink·바이너리는 제외합니다. 질문에는 모름·추천·보류로 답할 수 있고, 확인되지 않은 값은 확정 사실로 처리하지 않습니다. 생성된 해석·요구는 근거와 함께 검토하세요.

프로세스가 중단되면 마지막 확정 상태를 복원합니다. 이전 AI 프로세스의 종료가 불명확하면 새 실행을 막고 직접 정리한 뒤 확인하도록 안내합니다. 중단된 모델 작업은 자동 재실행하지 않습니다. 대화·비판 검토의 응답 형식이 잘못되면 한 번의 보정 호출이 추가될 수 있습니다. 질문의 선택지 수·UTF-8 길이 등 응답 제한을 모델에도 전달하며, 초과하면 항목과 실제 크기·한도를 표시합니다. 실패한 응답은 대화 내용에 반영하지 않고, 종료가 확인된 대화는 **답변 다시 받기**로 명시적으로 재시도할 수 있습니다. 설계 패키지의 형식 오류는 자동 재호출하지 않고 실패를 보여줍니다. 문서 저장은 파일 hash와 manifest로 복구하며, 예상 밖 외부 편집은 충돌로 남깁니다.

시간 초과 화면에는 해당 작업에 적용했던 제한을 표시합니다. **시간 제한 조정**에서 값을 저장한 뒤 **초안 다시 생성** 또는 **남은 문서 이어 만들기**를 누르면 기존 대화로 설계 작업을 시작합니다. 대화 실패에는 **답변 다시 받기**를 사용하세요. 설정을 바꾸거나 화면을 다시 열어도 실패한 작업을 자동 재실행하지 않습니다. 작성 중에도 적용된 제한을 확인하거나 **중지**를 선택할 수 있습니다.

문서별 요청에도 기본 **1800초**, 최대 **3600초** 설정을 그대로 적용합니다. 같은 생성 작업의 각 요청은 시작할 때 캡처한 모델·생각 수준·시간 제한을 유지합니다. 실패 후 새 작업으로 이어 만들면 현재 도구 설정을 적용하고 문서별 생성 설정을 기록합니다. 대화 입력·출력 언어·생성 규칙이 바뀌면 새 생성으로 시작합니다. 기본 생성은 문서 요청 10회와 전체 비판 검토 요청으로 구성되며, 공통 문맥을 반복 전달하므로 총시간과 토큰 사용량은 모델·문서 깊이에 따라 달라집니다.

## 개발과 검증

소스 빌드에는 Rust stable과 C 컴파일러(SQLite 빌드)가 필요합니다. 검증 환경은 Rust 1.99.1이며, 프런트엔드 검증에는 Node.js 20 이상을 사용합니다. 제품 실행에는 Node·별도 웹 서버·프런트엔드 빌드가 필요 없습니다.

```bash
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test --locked
npm run test:web
cargo build --release --locked
```

브라우저 자동 검증은 별도의 개발 의존성입니다. 설치된 Chrome의 새 headless 프로필과 임시 프로젝트만 사용하며 기존 사용자 탭에 연결하지 않습니다. 실제 모델을 호출하지 않는 명시적 CLI fixture로 화면을 검증합니다.

```bash
npm ci
npm run test:browser
# Chrome이 없는 환경: npx playwright install chromium
# ARCHITALK_BROWSER_CHANNEL=chromium npm run test:browser
```

일반 테스트는 모델을 호출하지 않습니다. 설치된 CLI와 실제 모델을 사용하는 검증은 별도로 실행하며 사용량이 발생할 수 있습니다.

```bash
cargo test --test ai_adapter real_ -- --ignored --nocapture --test-threads=1
cargo test --test real_workflow -- --ignored --nocapture --test-threads=1
cargo test --test real_document_format -- --ignored --nocapture # Codex 설계 1회
cargo test --test real_project_isolation -- --ignored --nocapture # Claude/Codex 짧은 요청 각 1회
cargo test --test real_conversation -- --ignored --nocapture # Claude 실제 첫 대화 계약 1건
```

두 번째 명령은 실제 바이너리→로컬 HTTP/SSE→CLI 대화·설계·검토→문서 저장→재시작을 임시 프로젝트에서 확인합니다. [검증 실행 이력](tests/test-history/README.md)에서 성공·실패·미실행 범위를 구분합니다.

| 모듈 | 책임 |
| --- | --- |
| [app](src/app.rs) · [model](src/model.rs) | 상태 변경·버전·중복 명령·작업 조율 |
| [domain](src/domain.rs) · [design_package](src/design_package.rs) | 질문 선택·근거·수정 이력·검토 게이트·10종 문서 형식과 추적성 |
| [ai](src/ai.rs) | Claude/Codex 호출·출력 해석·취소·시간/크기 제한 |
| [storage](src/storage.rs) · [files](src/files.rs) | SQLite·잠금·고정 디렉터리 경계·자료 탐색·새 문서 저장 |
| [http](src/http.rs) · [web](web/app.js) | 인증된 로컬 API/SSE·실제 웹 UI |

## 지원 경계

AI 작업은 프로젝트의 `.architalk/runtime/` 안에서 실행하고 macOS `sandbox-exec`로 CLI 파일 쓰기를 해당 실행 디렉터리로 제한합니다. 기존 CLI 인증은 읽어 재사용하며 공용 홈에 프로젝트 세션·로그를 쓰지 않습니다. 인증 갱신에 공용 파일 쓰기가 필요한 경우에는 터미널에서 해당 CLI에 다시 로그인해야 합니다. 관리형 CLI 정책을 검증할 수 없거나 필요한 제한을 적용할 수 없으면 실행을 거부합니다. 현재 릴리스 대상은 macOS와 로컬 파일시스템이며 Linux·Windows 빌드/AI 실행, 네트워크 공유 폴더, 임의 named profile은 아직 지원하지 않습니다.

Codex는 실행용 `CODEX_HOME`도 프로젝트 runtime 안으로 분리하고, 기존 파일 인증을 읽기 링크로 재사용합니다. 인증 파일은 복사하지 않습니다. 현재 Codex 프로필은 파일 인증 또는 기존 API-key 환경을 사용하며, 키체인에만 저장된 인증은 지원하지 않습니다. Claude의 기존 로그인은 그대로 재사용합니다.

부모 프로세스의 강제 종료·전원 손실·임의로 분리된 프로세스까지 정리를 보장하지 않습니다. 중단 뒤 종료 미확인 게이트를 유지합니다. 원격 공동 편집·코드 구현/수정·전체 저장소 무제한 탐색은 제공하지 않습니다. 문서 HTML과 생성 SVG를 정화하고 문서의 스크립트·앱 제어 속성·자동 외부 리소스 요청을 차단합니다. 기본 진단은 stderr에 제한된 단계·오류만 기록하고 프롬프트·응답 전문·인증 정보를 로그로 남기지 않습니다.

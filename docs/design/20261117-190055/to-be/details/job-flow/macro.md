# ArchiTalk 매크로 흐름

관찰 경계는 브라우저·Rust 서비스·상태 DB·문서 writer를 포함한 ArchiTalk 전체다. 외부 객체는 사용자와 로컬 AI 실행 도구(Claude/Codex CLI)다. CLI 뒤 모델 서비스·인증은 CLI의 책임이며 여기서 내부를 펼치지 않는다. 계약 원본은 [시스템 설계 §4~§7](../../system-design-to-be.md)다.

## 대화 답변과 다음 설계 질문

```jobflow
scope: ArchiTalk와 사용자 및 로컬 AI 도구의 대화
Object: 사용자, 설계도우미, AI실행도구
사용자.On답변입력 --> 설계도우미.message.설계답변요청
설계도우미.message.설계답변요청 --> 설계도우미.대화실행판정
설계도우미.대화실행판정.실행가능 --> AI실행도구.message.대화해석요청
설계도우미.대화실행판정.설정확인필요 --> 사용자.message.AI설정확인안내
AI실행도구.message.대화해석요청 --> 설계도우미.message.대화해석결과
설계도우미.message.대화해석결과 --> 설계도우미.후보반영판정
설계도우미.후보반영판정.유효한현재후보 --> 사용자.message.설계요약과다음질문
설계도우미.후보반영판정.유효하지않은후보 --> 사용자.message.대화생성오류안내
```

- 사용자가 답하면 설계도우미에 답변과 기준 버전이 전달된다.
- 설계도우미가 현재 생성 작업·CLI 설정과 답변의 적용 가능성을 확인한다.
- 실행할 수 있으면 선택한 AI CLI에 고정한 문맥과 모델·생각 수준으로 해석을 요청한다.
- 설치·설정 확인이 필요하면 사용자에게 고치는 방법을 안내한다.
- AI 도구가 최종 결과 또는 오류를 설계도우미에 돌려준다.
- 설계도우미가 결과의 형식·참조·작업 버전을 검증한다.
- 현재 작업의 유효한 후보면 상태를 확정하고 요약과 다음 중요한 질문을 보낸다.
- 사용할 수 없는 후보면 미확정 결과를 버리고 사용자에게 오류와 재시도 경로를 보낸다.

접수 응답은 최종 답변이 아니다. 사용자 메시지를 먼저 저장하고 생성 상태를 표시한다. 모델 호출 없는 조회·요약은 저장된 상태에서 제공한다. 후보 repair가 필요한 경우 최대 1회 추가 호출하고, 늦은 결과나 취소된 작업은 상태를 덮어쓰지 않는다. 실행 중 변경 충돌과 중복 명령은 내부 계약에서 다룬다.

## 생성 중단과 종료 확인

```jobflow
scope: 사용자 중단과 로컬 AI 실행 종료
Object: 사용자, 설계도우미, AI실행도구
사용자.On생성중단 --> 설계도우미.message.생성중단요청
설계도우미.message.생성중단요청 --> 설계도우미.중단판정
설계도우미.중단판정.진행중인생성 --> AI실행도구.message.실행종료요청
설계도우미.중단판정.이미확정된결과 --> 사용자.message.이미완료안내
AI실행도구.message.실행종료요청 --> 설계도우미.message.실행종료결과
설계도우미.message.실행종료결과 --> 설계도우미.종료확인판정
설계도우미.종료확인판정.프로세스종료확인 --> 사용자.message.생성중단결과
설계도우미.종료확인판정.종료확인불가 --> 사용자.message.실행상태확인필요안내
```

- 사용자가 중단하면 설계도우미에 해당 작업의 중단 요청이 전달된다.
- 설계도우미가 결과 확정과 중단 중 어느 처리가 먼저 기록됐는지 확인한다.
- 진행 중이면 취소를 기록하고 AI 실행 도구의 프로세스 그룹 종료를 요청한다.
- 이미 결과가 확정됐다면 완료된 결과를 유지하고 그 사실을 사용자에게 알린다.
- 종료 요청의 결과를 받아 실제 자식 프로세스 종료를 확인한다.
- 설계도우미가 종료 확인과 미확인 상태를 구분한다.
- 종료가 확인되면 확정된 대화는 유지하고 미완료 생성은 중단됐다고 알린다.
- 종료를 확인할 수 없으면 실행 상태 확인이 필요함을 사용자에게 알린다.

중단 접수와 OS 프로세스 종료는 별개다. CLI의 네트워크 요청 취소·과금 취소는 보장하지 않는다. 프로세스 트리 종료는 지원 OS별 검증 대상이고 부모 급사 시 고아 프로세스까지 정리하는 보장은 별도 supervisor가 필요하다.

## 문서 반영과 충돌

```jobflow
scope: 설계 문서를 프로젝트 폴더에 반영
Object: 사용자, 설계도우미
사용자.On문서반영 --> 설계도우미.message.문서저장요청
설계도우미.message.문서저장요청 --> 설계도우미.저장가능판정
설계도우미.저장가능판정.현재버전과파일일치 --> 사용자.message.문서저장결과
설계도우미.저장가능판정.이름충돌또는외부수정 --> 사용자.message.문서비교와새이름제안
설계도우미.저장가능판정.쓰기오류또는부분반영 --> 사용자.message.저장오류와복구안내
```

- 사용자가 경로와 변경 미리보기를 확인하면 문서 저장 요청을 보낸다.
- 설계도우미가 문서 버전·대상 경로·기존 파일과 실제 쓰기 결과를 판정한다.
- 같은 버전의 새 출력 폴더에서 모든 저장 단계가 완료되면 경로와 저장한 내용 상태를 알린다.
- 이름 충돌이나 외부 수정이면 원본을 보존하고 비교·새 이름 경로를 제시한다.
- 쓰기 실패나 일부 반영이면 완료로 표시하지 않고 파일별 상태와 재시도 방법을 알린다.

파일 쓰기·DB export intent·manifest 대사는 설계도우미 내부 동작이며 [내부 저장 흐름](architalk.md#문서-출력과-재시작-대사)에서 펼친다. 초안도 저장 가능하며 저장 성공을 사용자 내용 승인으로 간주하지 않는다. 파일로 끝나는 작업에도 사용자에게 성공·충돌·오류 결과까지 전달한다.

## 검토 범위

이 도표는 제안 계약의 정적 검토 대상이다. AI 해석·취소·저장 세 사건을 다뤘고 설치 진단·단순 목록 조회는 계약표로 대신했다. DSL 렌더링·선 겹침과 실제 제품 동작은 별도 검증이며, 실행 이력에서 수행 범위를 확인한다.

# Diagram fit, zoom and pan — 2026-11-18

## Plan before implementation

The reported wide State diagram is clipped on the right and has a local
horizontal scrollbar. Current sanitizeSvg writes a 280–1600px minimum width and
the figure uses overflow:auto. Replace this display policy with a bounded
viewport: initial fit shows the entire diagram, explicit zoom buttons and reset
allow detail inspection, and pointer drag / focused arrow keys pan an enlarged
diagram inside the same box. No page or figure horizontal scrollbar is needed.
ResizeObserver recalculates fit after window/sidebar/container width changes.

SVG languages (Mermaid, State, Navigation, Jobflow) and generated Layout HTML use
the same viewport. Keep all existing untrusted markup/SVG sanitization, strict
Mermaid rules, CSP, diagram errors/source escaping and stale-render guards.
Trusted controls are created only after sanitization and use event listeners,
not inline actions. Default wheel/touch behavior continues document navigation;
panning activates only when an enlarged diagram exceeds its viewport.

Owned files: document-renderer.js, document.css, new diagram-viewport.js,
diagram-targeted tests and this record. Root owns the new static asset route;
another frontend agent owns the file viewer and app integration. Any file link
callback is coordinated through a server allowlist, without raw file navigation.

## Implementation and targeted green result

New `diagram-viewport.js` mounts trusted controls only around already-sanitized
output. The initial camera fits the whole SVG/Layout within a bounded height.
Explicit +/−/전체 보기 controls report actual scale; enlarged content is clamped
inside the camera and moved by captured pointer drag or focused arrow keys.
Very wide graphs can still reach their native text size. A ResizeObserver handles
container/sidebar/window width changes, and Layout remeasures after a hidden
panel becomes visible. Wheel behavior is untouched; native document touch motion
remains available at fit, with drag panning enabled only for enlarged overflow.

The renderer disposes old camera observers/listeners on document replacement and
keeps its generation/isConnected guards. A stale asynchronous diagram cannot
mount into a newer document. Existing Markdown/SVG sanitizers, Mermaid restrictions,
SVG ID isolation, literal source fallback and script CSP are retained. Camera
transforms contain numeric values generated by the viewport, and controls use
event listeners with no data-action or inline handler attributes.

The file-viewer agent and backend owner agreed the optional renderer contract
`currentFile`, `fileLinks` (server catalog canonical relative strings),
`onFileLink({path,anchor})`. Relative links resolve within project root and must
match that allowlist; comparison uses NFC while callback paths preserve the exact
catalog spelling, including macOS NFD. Same-file anchors use trusted heading IDs.
Cross-file callbacks never place the raw path in href or fetch/navigation it.
Existing package documentLinks/currentDocument callbacks remain available.

## Independent file-viewer race plan (before browser execution)

Root assigned a separate read-only source review and new
`tests/browser/viewer-races.spec.mjs` ownership. Two concrete races were reported
to the frontend owner before writing regression tests: a same-tab refresh could
null/replace tab.node while an earlier renderer import still used it, and an
inactive detached preview could lose an in-flight Mermaid result permanently.
The frontend owner corrected the source while these independent tests were
prepared; no pre-fix browser failure is claimed.

The new cases use the existing isolated product fixture, only temporary project
Markdown/text files and GET APIs. A network gate delays the actual renderer import
across a second same-file read, then requires only the new revision with no stale
promise error. Another gate delays Mermaid, switches through a second file and
chat, resolves the import while inactive, and requires the original cached tab's
complete diagram and fitted camera on return. Both cases forbid API mutations,
external requests and page errors. They do not use clipboard, microphone, model,
transcription, real user files or a user's server. Execute desktop/mobile only
after frontend ready and a frozen test binary path are supplied.

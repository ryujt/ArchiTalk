## INS-01 — 셸 계약과 임시 prefix 실제 설치

- 상태: 2026-11-18 08:08 KST 통과. `sh -n` 및 도움말·잘못된 옵션 4종, 공백을 포함한 상대 prefix 실제 설치, 다른 cwd에서 PATH 실행을 확인했다. 임시 설치는 정리했다.
- 방법: `sh -n install.sh`, help/잘못된 옵션 확인, 체크아웃 밖 cwd에서 공백을 포함한 상대 `--prefix`에 실제 Cargo 설치. 설치 파일의 `--version`, 해당 bin을 PATH에 넣은 다른 cwd에서 `architalk --help` 확인.
- 기대: 호출 cwd와 무관하게 올바른 소스 빌드, prefix는 호출 cwd 기준, 옵션 오류는 비정상 종료, 기존 사용자 셸 설정 변경 없음. 임시 경로는 해당 실행의 자원만 정리한다.

### INS-01R — 독립 검토와 안내 재검증

- 검토: 별도 Critic 에이전트가 읽기 전용 검토. 설치 대상과 기존 PATH 명령이 다를 때 새 설치 경로 안내가 생략되는 반례를 지적했다.
- 처리: 수용. prefix의 절대 설치 경로를 항상 출력하고 PATH 맨 앞에 둘 것을 안내한다. `command -v` 출력은 현재 PATH 결과라고 구분한다. 기본 설치도 Cargo가 출력한 bin 경로 우선순위를 안내한다.
- 1차 재검증: 셸 문법과 실제 설치는 성공했으나 검증 코드의 경로 문자열 비교가 실패했다. macOS 임시 경로의 `/var` 별칭과 스크립트가 출력한 실제 `/private/var` 경로의 차이였다. 설치 결과나 스크립트 결함은 아니며, 검증 코드에서 `Path.resolve()`로 실제 경로를 비교하도록 수정 후 재실행한다. 임시 설치는 예외 발생 후에도 정리됐다.
- 최종 결과: 실제 경로 기준 재검증 통과. 이미 전역 명령이 PATH에 있는 상태에서도 별도 prefix의 설치 파일·PATH 우선순위·현재 명령을 모두 구분해 출력하고, 새 설치 파일의 버전이 `architalk 0.1.0`임을 확인했다. 임시 설치는 정리했다.
- 독립 재검토: Critic이 변경된 안내를 확인하고 추가 지적 없음으로 보고했다. 작성·검증은 통합 담당, 반례 검토는 별도 에이전트가 맡았다. 모델은 상속 설정을 유지했다.

## INS-02 — 기본 사용자 경로 설치와 전역 명령

- 상태: 2026-11-18 KST 통과. 기본 `./install.sh`가 사용자 Cargo bin에 설치했고, `/tmp`의 새 `zsh -lc`에서 `command -v architalk`가 `~/.cargo/bin/architalk`로 해석되고 `architalk --version`이 `architalk 0.1.0`을 반환했다. 셸 설정 변경 없이 전역 실행 가능하다.
- 방법: 기본 `./install.sh` 실제 실행 후 다른 cwd의 새 login shell에서 `command -v architalk`와 `architalk --version` 확인.
- 기대: Cargo의 정상 설치 경로와 PATH에서 실행 가능. 사용자 전역 바이너리 설치는 이번 요청 범위다. 실제 앱 서버·모델은 시작하지 않는다.
